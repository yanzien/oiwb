# yanzien 信奥工作台 · 部署指南

本工作台采用 **前端单文件 + 可选双后端** 架构：

```
┌─────────────────────┐
│  oi-workbench.html   │  ← 单文件前端，零依赖、离线可用、数据存本地
│  （手机/电脑浏览器）  │
└──────────┬──────────┘
           │ 可选联网抓取
     ┌─────┴───────────────┐
     │                     │
┌────▼──────────┐   ┌──────▼──────────────┐
│ GitHub Actions │   │ Cloudflare Worker   │
│ 聚合爬虫(方向1) │   │ 洛谷直连兜底         │
│ 每30min抓CF/   │   │ 解析洛谷比赛列表     │
│ 洛谷/AC/牛客   │   │ Cache 20min + CORS   │
│ → contests.json│   └──────────────────────┘
└────────────────┘
```

- **不部署任何后端**：前端照样能用，比赛靠内置公共源（Codeforces/AtCoder/kontests/Vjudge）实时抓取。
- **部署后端**：抓取更全（含洛谷、题目列表、决斗预填），且频率更稳、不依赖公共代理。

## 1. 目录结构

```

backend/

└── 部署指南.md                         # 本文件
```

## 2. 前端部署（oi-workbench.html）

### 方式 A：本地直接打开（最省事）
双击 `oi-workbench.html` 用浏览器打开即可，所有数据存在浏览器 localStorage。
适合个人电脑使用。**缺点**：手机上不方便、文件传来传去。

### 方式 B：CloudStudio 一键部署（推荐手机党）⭐
在 WorkBuddy 里对包含 `oi-workbench.html` 的目录执行「部署到 CloudStudio」，
会生成公网链接。手机浏览器打开链接 → 分享 → **添加到主屏幕**，就变成一个 APP。
（部署后链接公开可访问，但数据仍在各自浏览器本地，互不干扰。）

### 方式 C：GitHub Pages
1. 新建仓库，把 `oi-workbench.html` 推上去（建议重命名为 `index.html`）。
2. 仓库 Settings → Pages → Source 选 `main` 分支根目录 → Save。
3. 几分钟后访问 `https://<用户名>.github.io/<仓库名>/`。

### 方式 D：任意静态托管
Vercel / Netlify / 对象存储 / 自己的服务器都行，把单个 HTML 文件传上去即可。

> 无论哪种方式，前端都是**纯静态、零后端依赖**。部署地址只是方便访问，数据永远在你自己浏览器里。

## 3. 部署 Cloudflare Worker（洛谷直连兜底）

用途：前端无法直接跨域访问洛谷（且有 Cloudflare 风控），用 Worker 在服务端解析后返回 JSON，并开启 CORS + 20 分钟缓存降低风控概率。

前置：一个 Cloudflare 账号（免费版足够）。

步骤：
1. 登录 https://dash.cloudflare.com → 左侧 **Workers & Pages** → **Create Worker**。
2. 给 Worker 起名（如 `luogu-contests`），编辑代码，把
   `backend/cloudflare-worker/luogu-contests.js` 的全部内容粘贴进去，保存并 **Deploy**。
3. 记下分配的地址，形如 `https://luogu-contests.<你的子域>.workers.dev`。
4. 在前端「比赛倒计时 → 数据源」里填入该地址（见第 5 节）。

验证：浏览器访问 `https://<你的worker>.workers.dev`，应返回 `{"ok":true,"source":"luogu-worker","contests":[...]}`。

> 免费额度：每天 10 万次请求，个人使用绰绰有余。20 分钟缓存意味着同一用户 20 分钟内只真正请求洛谷 1 次。

## 4. 部署 GitHub Actions 爬虫（聚合数据源）

用途：在云端定时聚合 CF/洛谷/AtCoder/牛客 的比赛（含题目列表），输出 `contests.json`，前端直接 fetch 这个文件，抓取最快最稳。

前置：一个 GitHub 账号。

步骤：
1. 新建一个**公开**仓库（如 `oi-contests`）。
2. 把以下文件按相同目录结构推上去：
   - `scrape.py`
   - `requirements.txt`
   - `.github/workflows/scrape.yml`
3. 仓库 **Settings → Actions → General → Workflow permissions**，把
   `Read and write permissions` 打开（爬虫需要自动提交 `contests.json`）。
4. 进入 **Actions** 标签页，应该能看到 `scrape-contests` 工作流；首次可点 **Run workflow** 手动触发一次。
5. 之后每 30 分钟自动跑一次，并把最新 `contests.json` 提交回仓库。
6. 拿到可访问的 JSON 直链，二选一：
   - **raw 直链**：`https://raw.githubusercontent.com/<用户名>/<仓库>/main/contests.json`
     （注意：raw.githubusercontent.com 带 CORS 头，前端可直接 fetch）
   - **GitHub Pages**：在该仓库开启 Pages（源选 main 分支根目录），用
     `https://<用户名>.github.io/<仓库>/contests.json`

7. 在前端「比赛倒计时 → 数据源」里填入该直链（见第 5 节）。

> 爬虫策略（已内置）：串行抓取、单平台间隔 ≥2s、连续失败 3 次暂停该平台、某平台失败不影响其他平台、统一转 UTC+8 时间。被风控时 `contests.json` 里对应平台为空但不报错，方便排查。

## 5. 前后端对接（在前端填 URL）

打开前端 → **比赛倒计时** 视图 → 右上角「数据源」按钮，填写：

| 字段 | 填什么 | 说明 |
|------|--------|------|
| GitHub Actions 数据源 | 第 4 节拿到的 `contests.json` 直链 | 提供 CF/洛谷/AtCoder/牛客 + 题目列表 |
| Cloudflare Worker | 第 3 节拿到的 Worker 地址 | 单独补洛谷直连，兜底用 |

两个都填最稳；只填其一也能用；全空则用前端内置公共源（走公共 CORS 代理，偶发不稳定属正常）。

填好后点「联网抓取」，日志面板会实时显示每个数据源的抓取进度。

## 6. 注意事项

- **隐私**：前端数据只存在你自己的浏览器 localStorage，不会上传到任何服务器。
  部署后的页面是公开链接，但**看不到你的任何数据**，请勿在公开页面预填真实隐私。
- **CORS**：本地 `file://` 打开时部分浏览器对 `fetch` 有限制，建议用方式 B/C/D 部署或本地起静态服务（`python -m http.server`）。
- **抓取频率**：不要高频刷新洛谷，Worker 已做 20 分钟缓存、爬虫间隔 2s，请保持，避免触发风控封 IP。
- **成本**：Cloudflare Worker 免费额度、GitHub Actions 免费额度对个人完全够用，无需付费。
- **数据备份**：前端首屏有「导出 / 导入」按钮，数据积累到 30 条会提示备份。换设备时先导出再导入。
- **洛谷风控**：若 Worker 返回 502 `data not found`，多为洛谷触发了 Cloudflare 验证，等几分钟缓存过期或换 IP 再试，不影响其他数据源。

## 7. 常见问题

**Q：不部署后端能干嘛？**
能。比赛用内置公共源实时抓（CF/AtCoder/kontests/Vjudge），题目/网站/工具全部本地可用。后端只是让洛谷和题目列表也能自动进来。

**Q：为什么洛谷必须走后端？**
洛谷有 Cloudflare 风控且禁止跨域，纯前端浏览器既拿不到数据也绕不过验证。Worker 在服务端代抓是唯一干净方案。

**Q：GitHub Actions 一直失败？**
检查：①仓库是否公开（私有仓库 Actions 也免费，但 raw 直链需公开才能被前端 fetch）；②`Read and write permissions` 是否开启；③看 Actions 日志里哪个平台报错，按需调 `scrape.py`。

**Q：手机怎么用最爽？**
用方式 B 部署到 CloudStudio 拿到链接，手机浏览器打开 → 分享 → 添加到主屏幕，体验等同 APP。

**Q：比赛题目列表 / 决斗预填？**
GitHub Actions 数据源的 `contests.json` 已带 `problems` 数组（CF 稳定、其余 best-effort）。后续可在比赛详情里加「题目列表 + 一键预填到决斗」按钮，按需迭代。
